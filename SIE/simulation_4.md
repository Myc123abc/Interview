## ご自身のゲームエンジンでは、具体的にどのような設計をしていますか？
```
はい。例えば、リソースを複数のコマンドキューで使用する場合、キュー間の同期が必要になります。
最初は、この同期を手動で管理していました。
しかし、処理が複雑になるにつれて、ミスの発生し、GPUのエラーが起きることもありました。
そこで、自動的に同期できる仕組みを設計しました。
コマンドごとに、使用するリソースの状態を記録します。
そして、コマンドをGPUに送る前に、現在のコマンドと、以前のコマンドで使用したリソースを比較します。
その結果から、必要なキュー間の同期を自動的に決定します。
このように自動化処理することで、リソースの状態遷移とキュー間の同期を、より簡単に管理できるようにしました。
以上です。
```
## 具体的に、どのように同期が必要かを判断していますか？
```
はい。同期が必要かどうかは、リソースの使用状況を見て判断します。
例えば、リソースはキューAに書き込み、キューBで読み込む場合です。
この場合、キューBはキューAの書き込みが完了するの待つ必要があります。
そのため、キュー間の同期が必要になります。
リソースの使用状況については、現在は読み込みと書き込みの二つの状態を記録しています。
以上です。
```
## では、例えばキューAでリソースを読み込んだ後に、キューBでも同じリソースを読み込む場合はどうでしょうか？この場合も同期は必要だと考えていますか？
```
はい、この場合は、同期は必要ありません。
実装では、読み込みを０、書き込みを１として、
ビット単位のORで判断しています。
そのため、読み込み同士の場合は０になり、同期は必要あります。
この方法が一番シンプルだと考えています。
以上です。
```

```
はい、リソースを二つのキューで書き込む場合は、同期が必要です。
先ほどのビット操作では、書き込みを１としているので、１と１のORの結果は１になります。
そのため、同期が必要だと判断ります。
以上です。
```
